---

There are plenty of places to learn how to code.

You can follow a course. </br>
Solve a hundred problems. </br>
Build another to-do app. </br>
Collect a certificate.

And then you can open a blank repository and ask:

**"What should we build?"**

That's where CodexClava begins.

We are a community of people who want to go beyond learning software development and actually **practice it** together.

We build things. We break things. We argue about how to build them. We change out minds. We ship. We learn.

And then we do it again.

## What we're here to do

Build software that is worth building.

Sometimes that's a serious project. Sometimes it's a weird experiment. Sometimes it's a tool that solves a problem only ten people have.

It doesn't matter.

What matters is that it starts with curiosity and ends with something real.

Our projects can take many forms:

* open-source software
* web and mobile applications
* developer tools
* AI experiments
* infrastructure
* security projects
* research
* automation
* things we still haven't thought of yet

We don't want to decide everything in advance.

The interesting stuff happens when people are given room to explore.

## How we learn

The project is the classroom.

You don't learn databases because someone told you to learn databases.

You learn them when the database becomes the hardest part of the thing you're trying to build.

You learn distributed systems when one server isn't enough.

You learn testing when a change breaks something you thought was unrelated.

You learn Git when six people need to work on the same codebase without destroying each other's work.

You learn leadership when a team needs someone to make a decision.

That's the kind of learning we're interested in.

**We emphasize less on "finish the tutorial".** </br>
**and more on "let's figure this out."**

## How we work

Most of the work happens in the open.

Ideas become discussions.

Discussions become issues.

Issues become pull requests.

Pull requests get reviewed.

Good work gets merged.

And eventually, someone uses what we built.

You don't need permission to have an idea.

You don't need to be an expert to contribute.

You don't need to write code to matter here.

A good design, a thoughtful review, a useful investigation, a well-written explanation, or a difficult question can move a project forward just as much as a feature can.

## The people

Some members will have years of experience.

Some will be writing their first serious program.

That's fine.

We don't want a community where beginners are spectators and experienced people do all the work.

We want people to **grow into responsibility**.

Start with a small issue.

Then take a bigger one.

Help someone else.

Review someone's work.

Lead a project.

Start one.

The person who joins today should have a path to becoming someone who can lead tomorrow.

## What we care about

**Curiosity.** </br>
Ask why.

**Ownership.**</br>
If you see something worth fixing, do something about it.

**Craft.**</br>
Small details compound.

**Honesty.**</br>
If it doesn't work, say so.

**Generosity.**</br>
Leave things better than you found them.

**Ambition.**</br>
Try things that might be too difficult.

**Humility.**</br>
Good ideas can come from anywhere.

## Open source

Whenever we can, we build in public.

Not because every project needs an audiance.

Because software becomes more valuable when knowledge doesn't stop with the person who wrote it.

If something we build can help someone outside CodexClava, we'd like them to use it.

If they can make it better, we'd like them to contribute.

The repository shouldn't belong to the person who started it.

**It should belong to the people who care enough to improve it.**

## If you're new

Don't worry about finding the perfect place to start.

Look around.

Find something interesting.

Read the code.

Ask a question.

Fix something small.

Make a pull request.

Your first contribution might be tiny.

That's how most things begin.

## And if you have an idea...

Bring it.

It doesn't need to be polished.

It doesn't need a pitch deck.

It doesn't need a hundred users.

It just needs to be interesting enough that you want to find out what happens if you build it.

Open an issue.

Start a discussion.

Find someone who wants to work on it.

See where it goes.

## One day

We want someone to discover a CodexClava repository years from now and find something they can actually use.

We want members to look back at their first pull request and barely recognize the developer who wrote it.

We want projects to continue after their original creators leave.

And we want people to come here with an idea they couldn't build alone...

...and leave having built something they didn't they could.

That's enough of a mission for us.
